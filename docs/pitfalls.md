# 踩过的坑

按踩到的顺序编号追加，编号不变。每条写：现象、原因、修法、→ 对后续工作的启示。
由此得出的行为规则写进 [AGENTS.md](../AGENTS.md)，并标注“坑 n”。
文中 §n 指 [project-notes.md](project-notes.md) 的章节，D-n 见 [decisions.md](decisions.md)。

坑 1–11 是 2026-10-03 从旧版项目须知整理出来的（D-1），日期是原文记下的发现日期；
没写日期的是 2026-09 期间陆续踩到的。

1. **较新 SDK 下所有含 `@State` 的文件编不过**（2026-09-21 解决）—— CLT 升到 Swift 6.4 后，
   较新 SDK 的 SwiftUI 把 `@State` 声明成了宏，展开需要只随 Xcode.app 分发的
   `SwiftUIMacros` 插件。MacOSX26 的 SwiftUI 还没这么做。

   修法：`build.sh` 按 26 → 26.5 顺序探测 SDK，不取 27。

   这个坑留下过一道疤：解决之前 UI 文件长期只有部分类型检查。解开后第一次全量检查，
   发现 `PopoverView` 还在用早已改掉的旧签名 —— 那个缺口连编译期错误都在吞。

   → 启示：改完 `Sources/App/` 必须跑全量类型检查；别改 SDK 探测逻辑。

2. **钥匙串授权框每次重新构建后、每条条目各弹一次**（2026-09-24 实机）—— 条目的访问控制
   列表记的是程序签名，ad-hoc 签名就是二进制哈希，重新构建就换了一个程序。
   `KeychainStore.set` 先删后加，新条目属于当前构建，所以重新粘 key 保存不弹；EXT-010 的存档
   切换去读旧构建存下的条目，于是弹。对最终用户就是每次升级、每个账户各一次。

   另一个前提：只能用文件版钥匙串，不设 `kSecUseDataProtectionKeychain`。数据保护版要求
   `keychain-access-groups` 权限，那随 provisioning profile 分发，本项目没有。

   修法：用户接受现状（方案 A）。议过的两条：固定的自签名证书（要用户手动生成）；把访问
   控制放开给所有程序 —— 否决，等于让本机任何进程都能读走能花钱的 key。根治见 §6 的
   Developer ID 方案。

   → 启示：「只弹一次」的说法不准确；实测钥匙串行为时要区分同一构建与重新构建。

3. **一个本该报失败的用例让整轮测试崩溃，看不出是哪条** —— 自建框架断言失败不中止，也没有
   进程隔离。`XCTAssertEqual(points.count, 1)` 失败后继续执行 `points[0]`，数组为空即崩溃。
   （2026-09-30 更正：真 XCTest 默认也不中止，但有进程隔离。）

   修法：新断言用 `points.first?`。现有 28 处 `[0]` 不专门改，改到那一段时顺手换。

   → 启示：count 断言挡不住后面的下标越界，在哪套框架里都一样。

4. **新写的测试静悄悄地不存在** —— 框架不做自动发现，用例要在
   `Tests/CoreTests/TestRegistry.swift` 显式登记，漏登记不报错。

   修法：新增测试后核对登记，并确认总数随之增加。

   → 启示：测试数没涨就是没登记。

5. **弱测试：用例被另一条规则顺带兜住，缺陷测不出** —— 反向验证抓到过 4 个弱测试和 2 个
   写错的断言。例：「三天断档」同时跨了日界，日界规则先兜住，间隔规则的缺陷测不出；
   EXT-001 的「长周期不该被避开」把剩余额度设得低于危险线，走了另一条分支而同样返回正确
   答案；采样间隔取得比 30 分钟空档阈值还大，断开来自「空档」而非要测的原因。

   修法：构造只命中目标规则的用例，每修一处做反向验证。

   → 启示：「测试通过」不证明测到了目标规则。

6. **缺陷注入静默失败，「全绿」被误读成「缺陷没被抓到」** —— 用 `perl -0pi -e` 做多行替换时
   锚点没命中，不报错也不改文件。

   修法：改用带 `assert` 的 python 脚本，先断言锚点存在，再替换。

   → 启示：注入本身也要能失败。

7. **脚本改中文文件时写进乱码字符 U+FFFD** —— 锚点坏了替换会失败，正文坏了会悄悄写进文件。

   修法：每次改完扫一遍：`grep -rn $'\xef\xbf\xbd' Sources Tests docs README*.md AGENTS.md`；
   锚点尽量用纯 ASCII 片段。

8. **macOS 的 `xargs` 没有 `-a`** —— 照 GNU 习惯写的命令直接报错。

   修法：`tr '\n' '\0' < file | xargs -0`。

9. **本机实验室漏掉 npm 缓存，事后从 `~/.npm` 里逐条删**（2026-09-28 / 29）—— 实测中转站软件时，
   第一个实验室没把包管理器缓存指进实验室目录。

   修法：全部放在 `/tmp/codapace-lab/`，只监听 `127.0.0.1`；`npm_config_cache`、
   `BUN_INSTALL_CACHE_DIR` 指进实验室，设 `NEXT_TELEMETRY_DISABLED`。清除后检查进程、端口，
   以及 `~/Library/Preferences/nextjs-nodejs` 这类目录。PostgreSQL 用 Maven 上 zonky 的便携版
   （`embedded-postgres-binaries-darwin-arm64v8`，jar 里是 `postgres-darwin-arm_64.txz`），
   Redis 从源码 `make`（模块编译失败不影响 `redis-server`）。

   → 启示：照供应商文档写适配器会错好几处，要实测；实测的痕迹要能完整收回。

10. **app 已在运行时 `open` 只激活旧实例，看到的不是新构建**。

    修法：先 `pkill -f "CodaPace.app/Contents/MacOS/CodaPace"; sleep 1`，再 `open`。

11. **`ditto` 是合并进已有 app，不是替换**（2026-09-26）—— 命令行升级不先删旧 app，会留下
    旧版文件。

    修法：README 的升级步骤改为先退出、`rm -rf` 旧 app，再安装。已发布的 v2.0 Release 说明
    仍是旧写法，没改线上内容。

12. **整轮测试崩溃时，最后打印出来的那条不是崩溃的那条**（2026-10-06）—— 反向验证注入缺陷后，
    有的用例断言失败、接着 `[0]` 越界（坑 3），整轮崩溃。输出接到管道时 stdout 是整块缓冲的，
    崩溃时还没刷出去的结果全丢了，看到的「最后一条」比真正崩溃的那条早得多。

    修法：用伪终端跑，输出按行刷新；同时关掉崩溃时的交互式回溯，否则它会停下来等按键：
    `SWIFT_BACKTRACE=enable=no script -q /dev/null swift run CoreTests < /dev/null`。
    输出带颜色控制符，grep 前先去掉。崩溃的是最后一条结果之后、登记表里的下一条。

    → 启示：先确认输出是按行刷新的，再按输出顺序判断崩在哪。

13. **删一个概念时只搜了标识符，注释里的中文叫法漏掉了**（2026-10-06）—— D-2 删能力声明时，
    按成员名 grep 已经干净，`TuziProvider` 里「这不是偷懒,是能力声明的兑现」这句却没搜到，
    留下一句和代码对不上的注释，直到 /simplify 审查才发现。

    修法：标识符和它在注释里的中文叫法（这次是「能力声明」）都要搜。

    → 启示：这套代码的注释用中文称呼概念，删改一个概念时两种写法都查一遍。
